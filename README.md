# Cognitrix Mobile

The iOS/Android app for [Cognitrix](../cognitrix). It uses the **same Supabase project** as the website, so accounts, enrollments, progress, quiz scores, bookmarks, Q&A and achievements are shared. Students can start a lecture on the laptop and finish it on the phone.

Built with Expo SDK 57, Expo Router, Supabase JS and TanStack Query.

## Setup

1. Install dependencies:
   ```sh
   npm install
   ```
2. Create `.env.local` (git-ignored) with the website's values, renamed from `VITE_` to `EXPO_PUBLIC_`:
   ```
   EXPO_PUBLIC_SUPABASE_URL=...        # = VITE_SUPABASE_URL
   EXPO_PUBLIC_SUPABASE_ANON_KEY=...   # = VITE_SUPABASE_ANON_KEY
   EXPO_PUBLIC_AI_API_KEY=...          # = VITE_AI_API_KEY (Gemini, used by the AI tutor)
   ```
3. Run both migrations **once** in the Supabase SQL Editor:
   - `supabase/migrations/mobile_push_notifications.sql` adds push notifications and the inbox (`push_tokens`, `notifications`).
   - `supabase/migrations/mobile_offline_sync.sql` adds offline sync: a `lectures.offline_video_url` column plus the `complete_lecture` / `submit_quiz` / `add_watch_time` functions.

   Both only add things, so the website is unaffected. The app also works without them, with no notifications and with older, less safe progress syncing.
4. Start the app:
   ```sh
   npx expo start
   ```

## Push notifications

| Event (from web *or* app) | Who is notified |
| --- | --- |
| Professor/TA answers a question | The student who asked |
| Enrollment request approved | Student |
| Enrollment request rejected | Student |
| Student requests to enroll | Course professor |
| Student asks a question / flags "stuck" | Course professor |
| New lecture added to a course | All enrolled students |
| New quiz added | All enrolled students |

These are generated by Postgres triggers and sent through the Expo Push API using `pg_net`, so no extra server is needed. Every notification is also stored in the in-app inbox (the bell icon). Tapping a notification opens the relevant lecture, course or Q&A screen.

**Remote push needs a development build.** Expo Go on Android doesn't support it. To enable it:
```sh
npm i -g eas-cli
eas init                 # links the project and writes extra.eas.projectId into app config
eas build --profile development --platform android   # or ios
```
Without a `projectId`, the app skips push registration. The inbox, realtime updates and the local **daily study reminder** (Account → Notifications) still work, including in Expo Go.

## Offline mode

Students can keep studying with no connection:

| Works offline | How |
| --- | --- |
| Every screen opened before (courses, lectures, progress, achievements, Q&A) | The query cache is saved on the device (SQLite) for 7 days |
| Watching **downloaded** lectures, reading downloaded PDFs/slides/attachments | **Downloads** (My Learning → Downloads, or the button on each lecture) |
| Mark complete, quizzes, bookmarks, notes, asking questions, watch time | Saved to an on-device outbox and synced automatically on reconnect |
| Transcript, topic list, daily reminder | Already on the device |

Online-only: streaming YouTube, the AI tutor, enrollment requests, and professor approvals and replies. The app tells students when they're offline instead of failing silently.

**Downloads are controlled by professors.** In the website's lecture form, *Allow offline download in the mobile app* enables it per lecture. YouTube lectures need an **offline copy**: the professor uploads the same video file (720p or lower recommended), and the app downloads that file. The app never downloads from YouTube. When a lecture has been downloaded, the app plays the local copy even when online, which saves the student's data.

**Safe syncing.** Offline actions are replayed through the database functions in `mobile_offline_sync.sql`. They add to progress inside the database instead of overwriting it, and replaying them is safe (a quiz has a client ID; completing a lecture twice counts once). So syncing an old offline change never erases progress the student made on the website in the meantime. The server re-grades quizzes; the phone's score is shown immediately for feedback.

**Storage:** the offline copies live in the existing `lectures` storage bucket (under `offline/`). Lecture videos are large (about 300 MB–1 GB per hour at 720p), so check your Supabase storage plan.

## What's in the app

**Students:** dashboard, course catalog (search/filter/sort), course details and enrollment requests, a player for YouTube and uploaded video lectures with topic-timestamp seeking, PDF/slides/links, mark complete, quizzes (MCQ, fill-in-the-blank, short answer), bookmarks and timestamped notes, lecture Q&A, the AI tutor, achievements and leaderboard, and My Learning.

**Professors:** dashboard stats, approve/reject enrollment requests, course list (owned and collaborations), Q&A replies and resolving "stuck" flags, and a switch to the student view. Course creation/editing, quiz generation and analytics stay on the website.

**Admins:** the admin console is on the website. The app offers the student view.

**Mobile-only extras:** push notifications plus the inbox, a daily study reminder, realtime refresh when something changes on the website, pull-to-refresh, haptics, and picture-in-picture for uploaded videos.

## Keeping web and mobile consistent

The website and the app both save progress through the SQL functions in `mobile_offline_sync.sql`, which are the single source of the points rules: +10 per lecture, +100 per course, and for quizzes, 10 + 40 × score% plus a +10 bonus at 100%, on the first attempt only. To change scoring, edit those functions and re-run the file. Both apps also keep a fallback copy of the rules, used only when the migration hasn't been run (`cognitrix/src/lib/progressApi.js` and `src/lib/sync.ts`).
